Developer Tooling

AI 開發工作流體系 — 自研多 LLM 調度引擎 + 開發流水線編排

把整個開發生命週期工程化成一條流水線，拆成上層編排、下層引擎兩層：上層 ticket-dashboard 用看板 UI 串起「抓票 → 分析 → 問答 → 規劃 → 實作 → review → 整合」；下層自研 harness-agent 是所有 AI 呼叫的統一入口，把 Claude Code / OpenAI Codex / Gemini CLI 三家異質介面抽象成同一組 runner。上層完全不直接呼叫任何一家 AI——換模型、加成本控制、加品質評分都不必動到編排邏輯。

  • 成本感知路由：關鍵字啟發式＋便宜模型分類 fallback 判斷任務類型，映射到 cheap / mid / strong 三層，簡單任務自動派便宜模型
  • affinity 自我學習：每次呼叫記帳 → 抽樣由 fresh-context 模型打分 → 聚合出模型適配度，下次同類任務優先派歷史高分模型
  • harness + loop 自動升降級：任務評分過低或失敗時，自動帶著失敗軌跡升級（換更強模型或換一家 AI）重試數輪
  • 雙盲二審（LLM-as-judge）：高風險判斷讓兩家 strong 模型並行獨立盲答，第三方模型裁決
  • 跨 AI 接續：換家時壓縮 ledger 塞進 prompt，省 90%+ token
  • 安全邊界：worktree/branch 與成敗判準一律由 deterministic script 負責，AI 不碰 Git、不自評成敗，每張票獨立 worktree 可並行

核心論點：精準記憶 vs 模糊記憶。任務有明確方向與已定案結論時，別靠 vector search 語意召回——改用檔案系統當結構化記憶，plan / analysis / 結論落地成可重讀的檔案。

同樣在鑫鼎鑽，我另外獨立建置一套自架 MCP server（不同專案，基於 Model Context Protocol），串接 Replica DB + CloudWatch 日誌，已實際跑在公司生產環境供工程團隊使用，harness-agent 本身則是個人本地開發工具。

Notable Side Projects

Developer Tooling

AI Dev Workflow System — Self-Built Multi-LLM Orchestration Engine + Dev Pipeline Orchestration

Engineered the entire dev lifecycle into a pipeline, split into two layers: an orchestration layer and an engine layer. The orchestration layer (ticket-dashboard) uses a kanban UI to chain "ticket intake → analysis → clarification → planning → implementation → review → merge." The engine layer (harness-agent), which I built myself, is the single entry point for every AI call, abstracting Claude Code / OpenAI Codex / Gemini CLI behind one interface. The orchestration layer never calls any AI provider directly.

  • Cost-aware routing: a keyword heuristic plus a cheap-model classification fallback determines task type, mapped to cheap / mid / strong tiers — simple tasks default to cheap models
  • Affinity self-learning: every call is logged and sampled/scored by a fresh-context model, aggregating into an affinity score so future tasks default to the historically best-scoring model
  • Harness + loop auto-escalation: on a low score or failure, automatically escalates to a stronger model or different provider and retries with the failure trace attached
  • Dual-blind review (LLM-as-judge): two strong models answer independently and blindly on high-stakes decisions, a third model adjudicates
  • Cross-AI continuation: cold handoff across providers compresses a ledger into the prompt, saving 90%+ of tokens
  • Safety boundaries: worktree/branch operations and pass/fail criteria are handled by deterministic scripts — the AI never touches Git or self-grades success; each ticket gets an isolated worktree so multiple tickets can progress in parallel

Core thesis: precise memory vs. fuzzy memory. When a task has a clear direction and settled conclusions, don't rely on vector-search semantic recall — use the filesystem as structured memory instead, with plans/analysis/conclusions written down as re-readable files.

Separately, at Fatpit, I built a standalone self-hosted MCP server (based on the Model Context Protocol) connecting to a replica DB and CloudWatch logs, actually running in production for the engineering team, whereas harness-agent itself is a personal local tool.
